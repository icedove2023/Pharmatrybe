# Clinical Decision Package Schema
Version: 1.0
Status: Architecture Locked
Project: PharmaTrybe

---

# Purpose

The Clinical Decision Package is the **single payload** returned by the
Clinical Decision Engine.

It combines

- Clinical Case
- SOAR prediction
- ARMD prediction (when applicable)
- WHO Knowledge Base
- Explainability

into one structured response for the Frontend.

The Frontend NEVER combines data itself.

Only the Decision Engine produces this package.

# request_information

Tracks the originating request.

| Field | Type | Required |
|---------|------|----------|
| request_id | UUID | Yes |
| timestamp | ISO8601 | Yes |
| clinician_id | String | Yes |
| institution | String | Yes |
| scenario | Enum | Yes |

Scenario

```
Scenario 1
Resistance Present

Scenario 2
Empirical Treatment
```

# Design Principles

The frontend never performs clinical reasoning.

The frontend never merges outputs.

The frontend never interprets WHO guidance.

The frontend only renders the Clinical Decision Package exactly as received.

---

# Contract Stability

This schema is considered stable after Phase 2.

Future versions may only add fields.

Existing fields must never change name or meaning.
