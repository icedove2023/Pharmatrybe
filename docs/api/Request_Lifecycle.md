# PharmaTrybe Request Lifecycle

## Purpose

This document describes the backend request lifecycle for the PharmaTrybe API bootstrap.
It defines how each incoming request is enriched with request metadata, timing information,
logging, security headers, and standardized error handling.

## Request Flow

1. A client sends a request to the FastAPI backend.
2. The request context middleware assigns a request identifier and request-scoped state.
3. Timing middleware begins measuring execution time.
4. Logging middleware records lifecycle details for observability.
5. Security headers are attached to the response.
6. The route handler executes.
7. If an exception occurs, the global exception handlers return a PharmaTrybe-standard error envelope.
8. The response is returned to the client with request and processing headers.

## Middleware Order

The middleware stack is registered in the following order:

1. Request Context
2. Timing Middleware
3. Logging Middleware
4. Security Headers
5. CORS
6. Exception Handlers

## Headers

Every request response includes:

- X-Request-ID: A UUID4 request identifier
- X-Process-Time: Total processing time in milliseconds
- Security headers for content type, framing, referrer, and XSS protection

## Logging

Every request is logged with:

- request ID
- HTTP method
- path
- status code
- processing time
- client IP
- timestamp

## Exception Handling

The backend converts framework and runtime errors into the PharmaTrybe API response envelope.

### Validation errors

Validation failures return:

- HTTP 422
- error code: VALIDATION_ERROR

### Unhandled errors

Unexpected failures return:

- HTTP 500
- error code: INTERNAL_SERVER_ERROR

### HTTP exceptions

FastAPI HTTP exceptions are translated into the same PharmaTrybe failure format using the matching documented error code.

```http
GET /health
X-Request-ID: <generated by middleware>
```

## Notes

This lifecycle infrastructure is reusable for future PharmaTrybe services and keeps the backend request pipeline consistent without introducing business logic.
